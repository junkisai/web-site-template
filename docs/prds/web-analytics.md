# アクセス解析

ページビューの数え方。

## 概要・提供価値

サイトの運営者が、ページビューの数を Cloudflare Web Analytics で見られるようにする。計測を使わないうちは、閲覧者のブラウザに計測のための JS を読み込ませない。

## 背景・解決する課題

- テンプレートのもとになった案件で足した仕組みのうち、中身に依存しないもの（アクセス解析の受け口）として切り出した（[product.md の「解決する課題」](../product.md#解決する課題)）
- Cloudflare の自動の設定には任せないので、トークンを手で入れるまでページビューは数えられない（`base-layout.astro` のビーコンの注釈）

## 対象ユーザー・スコープ

- 対象ユーザー・役割: ページビューを見るサイトの運営者。トークンを入れるテンプレートの利用者。計測される閲覧者
- 対象の画面・URL: すべてのページ
- できる操作: テンプレートの利用者がサイトのトークンを入れると、ページビューが数えられ、運営者は Cloudflare のダッシュボードで見られる
- 対象の範囲: ページビューを数えること
- 対象外: なし

## ゴール・成功条件

- トークンを入れたサイトで、すべてのページのページビューが数えられる
- トークンを入れていないサイトでは、閲覧者のブラウザが計測のために外へ接続しない
- 測定指標は決まっていない

## 振る舞い

- ページビューは Cloudflare Web Analytics で数える
- サイトのトークンを入れたとき → すべてのページで、ビーコン（`static.cloudflareinsights.com` の JS）を 1 つ読み込む
- トークンが空のとき → ビーコンを読み込まない。テンプレートの初期状態ではトークンは空で、ページビューは数えていない

## 業務ルール・制約

- トークンは、ページの HTML にそのまま出る公開の値
- 1 つのページで読み込むビーコンは 1 つだけ
- ビーコンは、サイトが外から読み込む唯一の JS（[site.md の「外部への接続」](site.md#外部への接続)）

## 状態遷移

なし

## 例外・境界条件

- トークンが空 → ビーコンを読み込まず、ページビューを数えない

## 受け入れ条件

- トークンが空のとき、出力の HTML に `cloudflareinsights` が出てこない
- トークンを入れたとき、各ページの HTML にビーコンの `<script>` が 1 つだけある
